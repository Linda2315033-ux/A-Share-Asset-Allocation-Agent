# A股智能资产配置研究 Agent

**A-Share Asset Allocation Research Agent**

基于 Python、AKShare、规则驱动资产配置、历史回测、智谱 GLM 工具调用和 Streamlit 的A股主板智能研究系统。

> **项目定位：** 本项目为学术研究与工程实践项目，旨在探索金融数据处理、市场状态识别、动态资产配置与大语言模型工具调用的结合。不连接券商交易接口，不执行实盘交易，所有研究结果均不构成投资建议。

## 1. 项目简介

本项目面向沪深A股主板市场，尝试构建一个从行情数据更新到研究结果展示的完整Agent工作流程。

系统主要包含以下环节：

1. **数据管理**：维护股票历史行情、股票池、沪深300指数行情及相关元数据。
2. **智能增量更新**：识别需要更新的股票，减少不必要的重复下载。
3. **数据完整性检查**：检查交易日期、历史行情、股票池及ST状态等信息。
4. **市场状态识别**：利用沪深300指数的趋势与波动率判断市场环境。
5. **动态资产配置**：根据市场状态选择配置策略，确定股票和现金的目标权重。
6. **研究预览与历史回测**：生成组合研究快照，并分析历史净值、回撤和风险收益表现。
7. **GLM智能解读**：通过工具调用读取研究结果，使用自然语言解释市场状态、组合配置及风险。
8. **Streamlit可视化**：提供中文研究网页，展示策略、权重、回测结果和Agent解读。

本项目采用**Python规则引擎负责计算、LLM负责调用工具与解释结果**的设计。

大语言模型不直接决定交易指令，也不允许绕过Python程序中的风险控制和数据校验规则。

## 3. 系统工作原理

```text
AKShare / 本地历史行情
          |
          v
股票数据增量更新
沪深300指数及股票池信息维护
          |
          v
交易日与数据完整性检查
          |
          v
市场状态识别
（趋势 / 波动率）
          |
          v
动态策略选择
          |
          v
股票筛选与目标权重计算
          |
          v
经过校验的研究预览
          |
          +----> 历史回测与绩效分析
          |
          +----> GLM只读工具调用
          |
          +----> Streamlit可视化
```

### 3.1 市场状态识别

系统利用沪深300指数历史行情，结合短期和中期收益率、年化波动率等指标，识别市场趋势与风险环境。

市场判断用于辅助配置策略选择，而不是预测确定性的未来收益。

### 3.2 动态配置策略

研究系统包含以下策略类型：

| 策略 | 适用的研究情境 | 目标股票仓位 |
|---|---|---|
| `MOMENTUM` | 上涨趋势、波动相对正常 | 80% |
| `DEFENSIVE` | 下跌趋势、波动相对正常 | 30% |
| `LOW_VOLATILITY` | 震荡市场、波动相对正常 | 60% |
| `RISK_REDUCTION` | 高波动风险环境 | 40% |

以上为策略规则中的目标配置比例，实际组合还受到股票筛选结果、个股权重限制和数据校验条件的影响，不保证每次都能达到目标股票仓位。

系统保留现金配置，用于表达不同市场状态下的风险暴露差异。

### 3.3 股票筛选与权重计算

Agent结合成交活跃度、历史动量、波动率等指标筛选候选股票，并通过Python规则计算目标权重。

这一设计强调：

- 策略选择有明确的规则依据。
- 组合权重可以通过代码复现。
- 不由LLM直接生成无法验证的交易指令。
- 数据不足或校验不通过时，可以停止生成有效配置结果。

### 3.4 历史研究快照示例

在2026年10月14日的一次本地研究快照中：

- 市场环境：下跌趋势
- 选择策略：`DEFENSIVE`
- 入选股票数量：4只
- 目标股票仓位：30%
- 目标现金仓位：70%

这是**特定日期的历史研究预览**，并非当前实时投资信号。

## 5. 每日自动化与运行时间

### 5.1 计划执行时间

本项目计划通过GitHub Actions，在每个周一至周五的**北京时间17:30（UTC 09:30）**启动每日研究流程。

```yaml
on:
  workflow_dispatch:
  schedule:
    - cron: '30 9 * * 1-5'
```

其中：

- `workflow_dispatch`：允许手动启动。
- `schedule`：配置定时启动。
- `30 9 * * 1-5`：对应北京时间周一至周五17:30。

**注意：以上是计划采用的定时配置，当前每日定时工作流尚未正式启用。**

GitHub Actions可能延迟启动；周一至周五也不一定都是A股交易日，因此实际执行还需要结合交易日和数据状态检查。

### 5.2 北京时间16:00的安全限制

为避免使用尚未完整收盘的行情数据，项目对每日行情写入更新设置了时间限制：

| 时间 | 行为 |
|---|---|
| 北京时间16:00之前 | 禁止每日行情写入更新 |
| 北京时间16:00及之后 | 允许尝试更新，但仍需通过数据检查 |
| 只读检查模式 | 可以执行数据检查，不修改历史行情 |

这一限制由 `stock_agent_daily_automation_v3.py` 实现。

如果在北京时间16:00之前运行写入模式，程序将主动拒绝执行，并提示：

```text
Write mode requires at least 16:00 Shanghai time
```

这是预期的安全行为，不代表程序安装失败。

选择17:30作为计划执行时间，是为了在16:00安全限制之后为数据源更新预留一定时间。

**通过时间检查不代表数据已经完整。** 实际研究结果仍以交易日期、数据质量及校验结果为准。

- 如需在线GLM问答，需自行配置智谱API Key

```bash
cd A-Share-Asset-Allocation-Agent
```

本地运行研究流程需要准备：

```text

    │   └── qfq/
```

**仅克隆公开仓库并安装依赖，不能直接复现全部历史研究结果。**

```powershell

```

默认执行只读检查，不进行每日行情写入更新。

当数据检查通过但正式发布受到限制时，程序可能返回：


更新日志位于：

```text

```

该命令仍属于研究开发和测试流程，不代表生产级无人值守运行已通过验收。


```text

```

### 6.9 GLM智能问答

首先进行测试：

```powershell
python stock_agent_glm_daily_v1.py --self-test

python stock_agent_glm_daily_v1.py --check
```

在线问答需要配置智谱API Key。

在PowerShell当前会话中设置：

```powershell
$env:ZHIPU_API_KEY = "YOUR_API_KEY"
```

然后执行：

```powershell
python stock_agent_glm_daily_v1.py --ask "请解释最新研究预览中的策略、股票权重和主要风险。"
```

请勿将真实API Key写入源代码、README或公开GitHub仓库。

GLM主要用于读取通过校验的研究结果并进行解释，不直接执行股票交易。

### 6.10 启动Streamlit网页

当前已验证的基础网页入口为：

```powershell

```

在终端显示的本地地址打开网页。

网页需要读取已经生成并通过校验的研究预览。若缺少有效数据，页面可能提示先运行研究流程。

历史回测展示还可能需要：

```text

```

这些文件可位于项目根目录或相应输出目录。

没有有效回测数据时，系统不应编造历史收益或绩效指标。

## 8. 研究限制与风险说明

### 8.1 ST状态日期尚未独立核验

当前系统可以根据股票名称及相关快照识别ST状态，但尚不能独立证明相关信息在目标历史交易日的准确可得性。

因此，正式发布仍受到限制：

```text
formal_publication_allowed = false
```

研究预览与正式发布必须明确区分。

### 8.2 历史时点偏差

当前股票池及部分历史信息可能存在：

- 幸存者偏差
- 历史ST状态偏差
- 前复权价格修订
- 停复牌与退市处理偏差
- 历史信息时点可得性问题

相关问题尚需进一步研究和核验。

### 8.3 回测局限性

历史回测结果取决于样本区间、交易成本、调仓规则、流动性、现金收益和成交假设。

历史表现不保证未来收益。

### 8.4 数据更新风险

行情接口可能出现网络失败、延迟更新、字段调整或历史数据修订。

即使某只股票的最后交易日期已达到目标日期，也不代表其全部历史数据永远不需要复核。

### 8.5 云端自动化限制

GitHub Actions可能出现调度延迟、运行失败或网络异常。

数据备份恢复成功不等于每日更新和公开发布全流程已经通过验收。

研究结果应明确显示实际数据日期，避免将历史快照误认为实时市场信号。

### 8.6 数据与密钥安全

本项目不公开完整历史行情数据库，不在源代码中保存私有数据访问Token或GLM API Key。

私有行情通过受限权限访问，公开研究结果应仅包含适合发布的必要信息。
